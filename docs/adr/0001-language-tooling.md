# ADR-0001: زبان، مدیریت محیط و لایه‌ی داده‌فریم

**وضعیت:** پذیرفته‌شده (مهر ۱۴۰۵)

## زمینه
پایه‌ی کل پلتفرم. روی سرعت موتور، کتابخانه‌های در دسترس، و راحتی کار تیم و Claude اثر مستقیم دارد. زبان پیشنهادی Python 3.12 است (اکوسیستم کوانت، NumPy/Numba، آمار). انتخاب باز: ابزار مدیریت محیط و کتابخانه‌ی داده‌فریم.

## گزینه‌ها
| گزینه | مزایا | معایب | اثر بر قیدها | شکل پیاده‌سازی |
|---|---|---|---|---|
| **uv + Polars** | نصب و lockfile بسیار سریع؛ Polars سریع، کم‌حافظه، lazy و مناسب داده‌ی حجیم universe | Polars با برخی کتابخانه‌ها (مثل vectorbt) مستقیم سازگار نیست و تبدیل به NumPy/pandas لازم است | برای universe چندصدنمادی و کش معاملات بهترین کارایی | `pyproject.toml` با uv؛ ETL و کش با Polars؛ هسته‌ی عددی روی آرایه‌های NumPy |
| **uv + pandas** | بیشترین سازگاری با کتابخانه‌های کوانت و آمار؛ آشنا برای تیم | کندتر و پرمصرف‌تر روی داده‌ی بزرگ | ساده‌ترین مسیر؛ در P7 (همه‌ی ردیف‌ها) ممکن است گلوگاه شود | همان ساختار، با pandas در ETL |
| **conda/mamba + pandas** | نصب باینری‌های علمی (Numba، TA-Lib) بی‌دردسر روی ویندوز | کند؛ lockfile ضعیف‌تر؛ بازتولیدپذیری سخت‌تر | اگر پل اجرا روی ویندوز باشد، محیط یکسان با MT5 ساده‌تر | `environment.yml` |

**ابزارهای مشترک در همه‌ی گزینه‌ها:** pytest + Hypothesis، ruff، mypy، GitHub Actions.

## تصمیم
**uv + Polars** (Python 3.12). ETL، universe و کش با Polars؛ هسته‌ی عددی روی آرایه‌های NumPy. ابزارهای مشترک: pytest + Hypothesis، ruff، mypy، GitHub Actions.
